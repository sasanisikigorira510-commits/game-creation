# 返金台帳の移行リハーサルとSandbox結合試験準備

2026-09-28。ここまでの実施はローカルの合成データのみ。VPS、実機、実鍵、実残高、
通知URL、QA有効期限は変更していない。実際のSandbox返金試験はまだ実施していない。

## 新しい隔離コピーでのみ移行を検証する

`refund_migration.py` は既存バックアップを読み、新しい隔離候補を作るためのツール。
稼働DBの直接移行、候補の上書き、稼働への昇格、隔離解除は実装していない。

隔離Pythonの `run_refund_migration.py` に次の引数を明示する。

- `--backup`: 完成したバックアップ世代の絶対パス。付属JSONも必要。
- `--expected-sha256`: 別途保管・確認済みのダイジェスト。付属JSONから自動採用しない。
- `--instance`: バックアップのInstanceIdと照合する識別子。
- `--new-directory`: 存在しない候補ディレクトリ。親は所有者専用とする。
- `--prepare`: このフラグを付けた場合のみ、新しい候補ファイルを作成する。

初期動作は読取専用の事前検査。スキーマ、整合性、ダイジェスト、インスタンス、私有パスを検査する。
稼働ディレクトリ、WAL/SHM/journalがあるファイル、シンボリックリンク、欠けた返金台帳は拒否する。
ダイジェスト一致はバックアップの最新性を証明しない。古いバックアップも稼働には使えない。

候補作成では先に `RECOVERY-PENDING.txt` を作る。新しいコピーに返金台帳がなければ追加し、
既存の台帳がある場合は残高・不足・免除・再送履歴を保持する。返金再確認の状態だけは
古い成功/占有を消し、記録済みApple購入をすべて `migration_recheck_required` にする。
既存の残高・購入・認証・操作等は行単位の論理ダイジェストで不変を検証する。

完了時は `refund-migration.json` に候補ハッシュ、再確認件数、未完了ゲートを記録する。
プレイヤーID、認証トークン、レシート等は報告へ出さない。`ReadyForDeployment` は必ずfalse。
失敗時も候補は隔離したまま残す。自動削除・上書き・再使用をしない。
`instance-id` は作らないため通常factoryと定期ワーカーは候補を拒否する。

## 配布前に残るゲート

1. バックアップ後の購入・消費・免除と最新の削除履歴を独立して保全し、照合できること。
   Appleの取引取得だけで消費や担当者による免除を復元しない。
2. 同期/返金処理/バックアップを含む安全な停止と切替え、新旧コード互換性の審査。
   今回は稼働DBへの移行スクリプト、切替えfactory、インストーラを追加していない。
3. QA専用DB・認証・購入環境・通知入口・ワーカーを同じ対象へ結び、Productionと混在させない。
   既存QA gatewayは許可経路を限定しているため、通知経路を無条件に公開してはいけない。
4. 再照合タイマー、失敗待機/件数/鮮度の監視、外部通知先を審査して明示接続する。
5. 新しい配布物のハッシュと固定依存を検証。過去の署名固定済み配布物は書き換えない。
6. 実鍵の利用、サーバー変更、実機配布、通知URL設定は、対象と影響を提示し承認を得てから行う。

返金機能の導入後に旧実行ファイルへ戻すだけのロールバックは不可。
古いコードは返金DBを拒否する。古いバックアップへの単純差し替えも、確定済みの取引・免除を失う。
不具合時は取引の停止/隔離と履歴保全を先に行い、修正済み互換コードまたは履歴照合を伴う復旧を審査する。

## Sandbox結合試験の順序（未実施のチェックリスト）

この順序は専用の使い捨てテストアカウント/残高で行う。現在のiPhoneの保存データを流用しない。

1. 専用Sandbox構成、期限付きアクセス、バックアップ、管理者権限を確認。
   通知入口がまだ接続されていなければ停止。署名なしHTTP成功を代替証拠にしない。
2. 少額のSandbox購入の付与を1回確認。取引ID・環境・付与数と残高を私有の試験記録へ保存。
3. 未使用分の返金、再送、順序逆転を確認。二重減算・他アカウントへの適用がないこと。
4. 消費済み返金で不足を作り、有償消費だけが拒否され、無料召喚とバトルは利用できること。
5. 審査preview/commit、応答不明の同一RequestId再送、審査後の返金取消を確認。
6. 通知取り逃しを再照合で検知。通信失敗/再起動/タイマー停止時に古い成功が正常扱いされないこと。
7. 削除済みアカウントへの遅延通知を拒否し、データが復活しないこと。
8. 復旧候補で最新の削除/取引/免除を照合するまでは稼働させないこと。

Apple側で実際に再現できない通知種別は未確認として残す。合成通知の成功で実通知の項目を合格にしない。
CONSUMPTION_REQUESTとユーザー同意の扱い、未登録取引の調査、API制限対応も別途必要。
